# STRAY KIDS THIS&THAT 구성품 트래커 (인터넷 배포용)

이 폴더는 대시보드를 **진짜 인터넷 주소**에서 열고, 상태 변경이 **자동으로 클라우드에 저장**되도록 만든 프로젝트예요. 아래 순서를 그대로 따라오시면 됩니다. 한 번도 안 해봤어도 전부 브라우저 클릭만으로 끝나요 (터미널/코딩 필요 없음).

예상 소요 시간: 10~15분

---

## 0단계. 준비물

- GitHub 계정 (없으면 https://github.com/signup 에서 이메일로 무료 가입, 1분)
- Vercel 계정 (이미 회사에서 쓰고 계신 것으로 보여요 — retentionmathflat.vercel.app. 같은 계정으로 로그인하면 됨. 없으면 https://vercel.com/signup 에서 "Continue with GitHub"로 가입하는 게 제일 빠름)

---

## 1단계. GitHub에 이 폴더 올리기 (터미널 없이, 웹에서)

1. https://github.com/new 접속
2. Repository name에 `skz-thisandthat-tracker` 같은 이름 입력 → Public 또는 Private 아무거나 선택 → **Create repository**
3. 생성된 저장소 페이지에서 **"uploading an existing file"** 링크 클릭
4. 이 프로젝트 폴더 안의 파일/폴더 전체를 그대로 끌어다(드래그 앤 드롭) 놓기
   - `api` 폴더, `public` 폴더, `package.json`, `.gitignore`, `README.md` 전부 포함해서 올려주세요
   - 폴더째로 끌어다 놓으면 GitHub가 알아서 하위 폴더 구조(`api/state.js`, `public/index.html`)를 유지해줘요
5. 아래 **Commit changes** 버튼 클릭 (초록 버튼)

이제 GitHub 저장소에 코드가 올라갔어요.

---

## 2단계. Vercel에 배포하기

1. https://vercel.com/new 접속 (Vercel 로그인 필요)
2. **Import Git Repository** 목록에서 방금 만든 `skz-thisandthat-tracker` 저장소를 찾아 **Import** 클릭
   - 목록에 안 보이면 "Adjust GitHub App Permissions"를 눌러서 방금 만든 저장소에 접근 권한을 줘야 해요
3. 프로젝트 설정 화면이 뜨면 별도 설정 변경 없이 그대로 **Deploy** 클릭
4. 1~2분 기다리면 배포 완료 화면과 함께 `https://skz-thisandthat-tracker-xxxx.vercel.app` 같은 실제 주소가 생겨요

지금 접속하면 대시보드는 뜨지만, 아직 저장소(데이터베이스)를 안 붙였기 때문에 상단에 "⚠ 클라우드 연결 실패"라고 떠요. 3단계에서 해결해요.

---

## 3단계. 자동 저장용 저장소(데이터베이스) 연결하기

1. 방금 만든 Vercel 프로젝트 화면에서 상단 탭 중 **Storage** 클릭
2. **Upstash** (Redis) 선택 → **Install** / **Connect** 진행
3. 무료 요금제(Free) 선택 → 이름/지역은 기본값 그대로 두고 생성
4. 생성 후 "이 프로젝트에 연결(Connect to Project)" 화면이 뜨면 방금 만든 `skz-thisandthat-tracker` 프로젝트를 선택해서 연결
   - 연결하면 Vercel이 필요한 접속 정보(환경변수)를 자동으로 프로젝트에 넣어줘요. 직접 입력할 값은 없어요.
5. 연결하면 Vercel이 프로젝트를 자동으로 다시 배포해요 (Deployments 탭에서 진행 상황 확인 가능). 안 되면 Deployments 탭에서 최신 배포 옆 **⋯ → Redeploy** 클릭

배포가 끝나면 아까 그 URL로 다시 접속해보세요. 상단 상태가 "✓ 저장됨" 또는 "새 데이터로 시작"으로 바뀌면 성공이에요.

## 4단계. 처음 접속 — 회원가입 (초대 코드 필요)

배포 후 URL로 처음 들어가면 로그인/회원가입 화면이 떠요. **회원가입** 탭에서는 이제 초대 코드 + 닉네임(2~20자, 한글/영문/숫자) + 비밀번호(4자 이상)가 필요해요. 이메일은 여전히 필요 없어요.

- 회원가입을 아무나 못 하도록, 초대 코드가 있어야만 가입할 수 있게 막아뒀어요. 코드는 슬님(관리자 계정)만 발급/관리할 수 있고, 코드 하나당 딱 1명만 가입할 수 있어요 (가입에 쓰이면 자동으로 "사용됨" 처리돼서 재사용이 안 돼요). 나중에 판매를 하신다면 결제받은 사람에게만 코드를 하나씩 전달해주시면 돼요.
- 슬님 계정(닉네임 `BBOKLIMONY`)은 이 기능이 생기기 전에 이미 가입되어 있어서 그대로 로그인만 하면 되고, 별도 코드가 필요 없어요. 로그인은 원래부터 코드가 필요 없고, 코드는 **새로 회원가입할 때만** 필요해요.
- 각자 만든 계정(닉네임)마다 데이터가 완전히 분리돼서 저장돼요. 슬님이 만드신 닉네임으로 보유/교환 현황을 관리하고, 같이 쓰는 다른 분들은 본인 닉네임으로 회원가입하면 각자 자기 컬렉션만 보고 관리하게 돼요 — 데이터가 서로 섞이지 않아요.
- 비밀번호를 잊어버리면 복구 수단이 없어요(이메일을 안 받기 때문). 잊어버리면 새 닉네임 + 새 초대 코드로 다시 가입해야 해요. 중요한 데이터라 걱정되면 닉네임/비밀번호를 메모해두는 걸 추천해요.
- 로그인 상태는 브라우저에 쿠키로 오래 유지돼서, 한 번 로그인해두면 다음에 같은 브라우저로 들어올 때 자동으로 로그인돼 있어요. 다른 기기에서는 그 기기에서 한 번 더 로그인(또는 회원가입)하면 돼요.

### 초대 코드는 어떻게 발급하나요?

`BBOKLIMONY` 계정으로 로그인하면 탭 맨 오른쪽에 **"초대 코드 관리"** 탭이 하나 더 보여요 (다른 계정에는 이 탭 자체가 안 보여요). 여기서 메모(선택, 예: "트위터 @abc 판매분")를 적고 **코드 발급** 버튼을 누르면 8자리 코드가 하나 생성돼요. 이 코드를 결제받은 사람에게 전달해주시면, 그 사람이 회원가입 화면에서 코드를 입력하고 가입할 수 있어요. 같은 화면에서 아직 안 쓰인 코드는 **삭제**(취소)도 가능해요.

- **🖼️ 현재 화면 이미지로**: 지금 보고 있는 탭 하나만 PNG 이미지로 저장. 트위터/카톡에 바로 올리기 좋아요.

- **📄 전체 페이지 PDF**: 위와 동일하게 7개 탭을 전부 캡처해서, 한 페이지씩 들어간 PDF 파일 하나로 받아요. 인쇄/문서 공유용으로 좋아요.
- **🔗 공유 링크**: 로그인 없이도 볼 수 있는 나만의 공개 링크를 만들어줘요. 이 링크를 받은 사람은 **개요 / 구성품 보드 / 멤버별 갤러리 / 여유분 카드**만 읽기 전용으로 볼 수 있어요(수정 불가, 그 안에서 이미지/PDF로도 내보낼 수 있음). 교환 관리·분철 발송·전체 발송에 적어둔 상대방 닉네임/연락처/운송장번호 같은 정보는 이 링크에 절대 포함되지 않아요.
  - 링크가 유출됐거나 더 이상 공유하고 싶지 않으면 "링크 재발급" 버튼으로 기존 링크를 즉시 무효화하고 새 링크를 받을 수 있어요.

## 개인용 / 분철용 컬렉션 나눠서 관리하기

상단 탭 아래에 **"보고 있는 컬렉션: 분철용 / 개인용"** 토글이 있어요. 로그아웃 없이 이 토글만 눌러서 완전히 독립된 두 개의 진행 상황을 오갈 수 있어요.

- **분철용**: 원래 이 앱이 관리하던 그룹 분철용 진행 상황이에요 (구하는 중/교환중/보유 전부 별도로 저장됨).
- **개인용**: 순수하게 내 개인 소장용 컬렉션이에요. 같은 카드라도 분철용으로는 아직 구하는 중인데 개인용으로는 이미 갖고 있는 것처럼, 두 쪽이 서로 완전히 독립적으로 움직여요.
- 개요/구성품 보드/멤버별 갤러리/여유분 카드 탭은 토글에 따라 내용이 바뀌고, **분철 발송·전체 발송** 탭은 그룹 물량 배송용이라 "개인용"을 보는 동안에는 숨겨져요.
- 이미 보유 중인 카드에는 **"↔ 전환"** 버튼이 있어요. 누르면 그 카드 1개가 지금 보고 있는 쪽에서 반대쪽으로 옮겨져요 (예: 분철용으로 갖고 있던 카드를 개인용으로 전환). 이 전환 기록은 **교환 관리** 탭 아래쪽 "카드 전환 내역"에 날짜와 함께 남아요.
- **교환 관리** 탭은 분철용/개인용 구분 없이 하나의 표로 계속 쓰여요. 다만 거래를 등록할 때 "받은 카드는 소속"과 "줄 카드는 소속"을 각각 고를 수 있어서, 개인 소장 카드를 주고 분철용 카드를 받는 것처럼 서로 다른 소속끼리의 교환도 기록할 수 있어요.
- 처음 이 기능이 추가되기 전까지 쌓아온 진행 상황은 전부 "분철용"으로 그대로 이어지고, "개인용"은 새로 깨끗하게 시작해요. 기존 데이터가 사라지거나 섞이지 않아요.
- 이미 보유 중인 카드는 **보유 수량이 1개뿐이어도** "🔁 교환 제안" 버튼으로 교환에 내놓을 수 있어요. 누르면 보유 상태는 그대로 유지되면서 카드에 "교환 제안중" 표시가 뜨고, **교환 관리** 탭에 자동으로 거래 기록이 하나 생겨요 — 거기서 상대방 닉네임/연락처와 무엇을 받을지 채워나가면 돼요. 그 거래를 완료/취소하거나 삭제하면 카드의 "교환 제안중" 표시도 자동으로 사라져요. (카드에서 바로 "제안 취소"를 눌러도 동일하게 정리돼요.)

## 이미 배포된 사이트를 업데이트하는 법 (파일 여러 개를 한 번에 교체할 때)

기능이 추가되거나 오류가 고쳐진 새 파일 묶음을 받으면, 처음 배포할 때와 거의 똑같은 방법으로 GitHub에 다시 올리면 자동으로 업데이트돼요. 회원 정보나 사용자들이 저장한 데이터(Redis)는 GitHub/Vercel과 별개로 안전하게 그대로 남아있으니, 코드만 새로 올려도 기존 데이터가 사라지거나 초기화되지 않아요.

1. 받은 압축 파일(zip)을 컴퓨터에서 압축 풀기(더블클릭 또는 "압축 풀기") — 폴더 안에 `api`, `public`, `package.json`, `README.md` 등이 보이면 성공
2. 기존에 만들어둔 GitHub 저장소(`skz-thisandthat-tracker`) 페이지로 접속 → 파일 목록 위쪽의 **Add file → Upload files** 클릭
3. 압축 푼 폴더 안의 내용물 전체(`api` 폴더, `public` 폴더, `package.json`, `.gitignore`, `README.md` 등)를 **폴더째로** 끌어다 놓기 — 처음 배포할 때와 마찬가지로, 파일 선택 대화상자로 하나씩 고르면 폴더 구조가 깨지니 꼭 폴더 아이콘을 통째로 드래그해주세요
4. 업로드 미리보기에서 `api/auth.js`, `api/admin-invites.js`, `public/index.html` 같은 경로가 제대로 중첩되어 보이는지 확인
5. 아래 **Commit changes** 버튼 클릭 → 기존 파일들은 자동으로 "수정됨(modified)", 새로 생긴 `api/admin-invites.js` 같은 파일은 "추가됨(added)"으로 표시돼요
6. Vercel이 몇 초~1분 안에 자동으로 새 배포를 시작해요. Vercel 프로젝트의 **Deployments** 탭에서 "Building" → "Ready"로 바뀌는지 확인
7. 배포가 끝나면 사이트에 새로고침해서 확인 — 새 기능(초대 코드 입력란, 거울 키링 등)이 보이면 성공이에요
